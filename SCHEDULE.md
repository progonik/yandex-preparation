# Ten-day schedule

Complete the tasks in order. The numbering deliberately introduces primitives before combining them into production components.

| Day | Problems |
|---|---|

| 2 | E07–E12 |
| 3 | E13–E18 |
| 4 | E19–E20, M01–M04 |
| 5 | M05–M10 |
| 6 | M11–M16 |
| 7 | M17–M20, H01–H02 |
| 8 | H03–H08 |
| 9 | H09–H14 |
| 10 | H15–H20 |

## Daily routine

- Problem 1: no compiler, full interview simulation.
- Problems 2–4: normal editor, compiler only after the first implementation.
- Problems 5–6: strict timebox; if unfinished, write down the missing invariants before reading documentation.
- End of day: choose one solution and rewrite it from memory in 20 minutes.

Keep a short journal containing:

- the bug that consumed the most time;
- whether the race detector found anything;
- one cancellation or shutdown invariant;
- the API decision you would change.
